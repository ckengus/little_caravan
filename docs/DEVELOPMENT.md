# 개발환경과 구조

## 1. 기본 채택 환경

사용자가 데스크톱 개발환경을 계속 켜두지 않아도 GitHub·클라우드 Codex·브라우저로 개발과 확인을 반복한다. 휴대폰은 실제 조작·플레이 검수 기기다.

| 용도 | 기본 선택 |
| --- | --- |
| 언어 | TypeScript |
| 개발/빌드 | Vite + npm |
| 2D 장면·프레임 재생 | Phaser |
| 테스트 버튼/설정 UI | HTML/CSS; 초기 React 도입은 불필요 |
| 핵심 로직 테스트 | Vitest 등 가벼운 TypeScript 테스트 도구 |
| 웹 자동 검증 | Playwright 등, 환경 지원 시 적용 |
| 저장소·CI | GitHub + GitHub Actions |
| 웹 공개 테스트 | GitHub Pages 우선, 실제 계정 설정·권한 확인 필요 |
| 후속 APK | Capacitor + Android SDK/JDK/Gradle 기반 클라우드 빌드 |

M1에서 Node LTS 및 의존성의 공식 호환 조건을 확인해 실제 버전을 선택하고 .nvmrc와 package-lock.json에 기록한다. 이 문서는 미검증 버전 숫자를 고정하지 않는다. Phaser 주 버전은 예제·플러그인 호환성을 확인하고 기록한다. 도중에 자동으로 주 버전을 올리지 않는다.

외부 패키지 설치가 막히면 실패 로그와 필요한 도메인을 기록한다. 사용자에게 로컬 설치를 먼저 떠넘기지 않는다.

## 2. 목표 실행 명령 — M1에서 생성·검증할 계약

M1에서 package.json과 잠금 파일을 생성하고 아래 명령을 실행 검증했다.

- npm ci: 잠금 파일 기반 설치.
- npm run dev: 개발 서버.
- npm run build: 타입 검사와 배포 빌드, 산출 dist/.
- npm run preview: 빌드 결과의 로컬 확인.
- npm run typecheck: 별도 타입 검사.
- npm test: 핵심 로직 테스트; 테스트 미작성 상태를 통과로 위장하지 않는다.

## 3. 설계 경계

- src/domain/: 행동 상태·전투 계산·성장·거래 등 렌더러와 무관한 로직.
- src/game/: Phaser 장면·캐릭터 표현·애니메이션 어댑터·이펙트.
- src/ui/: 테스트 버튼·개발 패널·후속 게임 UI.
- src/data/ 및 public/game-assets/: 수치·런타임 데이터·PNG. 최종 위치는 중복 없이 정하고 아래 원본 폴더와 매핑한다.
- assets/art/references/: 외형 기준과 참고 이미지. 런타임 아틀라스로 오인하지 않는다.
- assets/art/source/: 새로 제작한 원본 및 프레임/부품. 기존 파일은 보존한다.
- docs/: 명세·결정·실제 상태.

M1은 src/domain, src/data, src/game, src/ui를 생성했다. 런타임 도형은 Phaser로 그리므로 public 복제 아트는 없다. 나머지는 필요한 시점에 생성한다. 구현 시 필요한 만큼 만들며 내용 없는 폴더만 대량 생성하지 않는다. 원본을 public에 수동 복제해 서로 다른 버전이 되지 않도록 복사/패킹 절차나 단일 경로를 정한다.

행동 결정, 애니메이션 재생, 실제 위치 이동, 타격 판정을 분리한다. 프레임 재생이 8~12회/초 정도여도 게임 입력·이동 계산을 같은 속도로 강제하지 않는다. 배속과 일시정지에 영향을 받는 게임 시간을 통일하고 타격 이벤트가 배속에서 중복되지 않게 한다.

## 4. 테스트 필드 주소·입력

기본 테스트 필드는 ?scene=character-lab 같은 정적 호스팅에 안전한 진입점을 사용한다. 정식 게임을 추가해도 테스트 필드는 유지한다. 경로 기반 라우팅을 쓰면 새로고침 404 대책을 함께 구현한다.

- 모바일 세로와 PC에서 캐릭터/버튼이 잘리지 않는다. 가로에서는 필드와 패널을 재배치할 수 있다.
- Pointer Events로 누르기/떼기/취소를 처리한다. 버튼 밖으로 이동, pointercancel, 창 포커스 상실 시 걷기가 계속되지 않도록 한다.
- 키보드는 선택 지원: A/D 또는 좌우 걷기, Space 베기 등. 화면에 실제 매핑 표시.
- 효과음은 사용자 입력 후 활성화하고 음소거를 제공한다. 시스템 오디오 정책 때문에 자동 재생 성공을 가정하지 않는다.

## 5. CI와 웹 배포

M1에서 설치→타입/핵심 테스트→빌드 워크플로를 만든다. Pages 배포는 main 반영 후 빌드 산출물을 올리는 방식으로 구성한다. 배포 워크플로 권한과 Pages의 Actions 소스 설정은 실제 확인한다.

프로젝트 Pages의 /little_caravan/ 하위 경로와 Vite base 및 이미지/JSON 로딩 경로를 맞춘다. 루트 절대경로 때문에 리소스가 깨지지 않게 한다. 환경에 맞는 base를 사용하고 배포 성공 전 예정 URL을 실제 URL이라고 보고하지 않는다.

PR은 CI 확인용으로 사용 가능하며 main 변경 시 웹 배포를 목표로 한다. 사용자 작업 브랜치를 덮어쓰거나 강제 푸시하지 않는다. 배포 활성화가 도구로 불가능하면 코드·빌드 검증을 마친 뒤 필요한 계정 설정만 안내한다.

## 6. 테스트 범위

- 의미 있는 단위 검증: 상태 전환, 공격당 1회 피해, CC 중단, 배속/일시정지/한 단계 진행, 범위 경계, 저장 버전 마이그레이션과 오프라인 시간 상한.
- 브라우저 스모크: 필드 로딩, 버튼 입력, 더미 생성→접근→공격, reset, 리소스 누락·콘솔 오류.
- 시각 수동 검수: 발 미끄러짐, 그립, 무기 가림, 복귀 연결, 좌우 반전, 축소 가독성.
- 모바일 실기기 검수: 터치 취소·화면 회전·앱 전환·복귀·발열/성능. 실제 미검증 시 그대로 표시.

테스트를 통과시키기 위해 임의의 성공 문구를 출력하지 않는다. 수동 검수와 자동 검수를 각각 기록한다.

## 7. 후속 APK

M6 전에는 APK를 우선하지 않는다. 도입 시 실제 Node·Capacitor·JDK·SDK·Gradle 호환 버전을 고정하고 debug APK를 CI artifact로 제공한다. release 서명키는 코드에 저장하지 않는다. 웹 소스를 앱 안에 포함하고 외부 개발 서버에만 의존하지 않도록 한다.

## M1 구현 기록 — 2026-10-29

- Node 24.19.0 / npm 11.9.0, TypeScript 5.9.3, Vite 7.3.7, Phaser 3.90.0, Vitest 3.2.7, Playwright 1.64.1. package-lock.json이 실제 설치 버전을 고정한다. Vite 요구 Node ^20.19 또는 >=22.12와 현재 Node의 호환을 확인했다.
- `Lab`은 렌더러 없는 상태/게임 시간 모델이다. 0.1초 애니메이션 경계를 분할 처리해 타격 이벤트와 CC 전환을 계산한다. 렌더링은 Phaser update에서 독립적으로 실행한다. 한 프레임 진행은 배속과 무관하게 다음 0.1초 경계까지 이동·피격 시간도 함께 진행한다.
- 수치와 상태 정의: src/data/actions.ts. 임시 피해·속도·범위이며 제품 밸런스 확정값이 아니다. 공격 시작 시 식별자를 증가시키고 각 공격의 이벤트 소비 여부로 중복 피해를 방지한다.
- 입력: Pointer Events, 포인터 캡처, release/cancel/leave/lostcapture/blur/비표시 전환에서 보행 해제. 자동 모드에서는 AI가 이동을 결정한다.
- `base: './'`로 Pages 하위 디렉터리의 빌드 자산을 상대 경로로 로드한다. 테스트 필드는 쿼리 진입점이며 기본 진입도 같은 필드다.
- 오디오는 리소스가 없어 비활성화했다. 음소거/사용자 제스처 활성화는 오디오 추가 시 구현한다.
- Phaser 번들이 약 1.21 MB (gzip 332 kB)로 Vite 크기 경고가 있다. 빌드는 성공하며 모바일 실기기 성능은 별도 검증 대상이다.
- 브라우저 다운로드 `cdn.playwright.dev`는 현재 네트워크 정책에서 403으로 차단되어 기존 시스템 Chromium을 사용했다. CI는 Playwright Chromium을 설치하도록 구성했으며 원격 실행은 미검증이다.

## M2 간결 연출 구현

actorView는 Lab 상태/elapsed만으로 표현을 샘플링한다. action의 hit×FRAME과 타격 시작을 공유하고 hero.ts에서 impact 유지 0.1초·offset·회전·포즈를 관리한다. Lab의 실제 위치와 visualOffset을 분리하고 공격별 렌더러 타이머를 두지 않는다. Vite assetsInlineLimit=0은 Phaser SVG 로더와의 데이터 URI 비호환을 피하며 Pages 상대 경로는 유지한다. 자세 규격과 PNG 교체 절차는 [리소스 계약](../src/game/assets/README.md)을 따른다. 이번 로컬 회귀: 단위 13/브라우저 8 통과, 원격 M2 결과 미확인.

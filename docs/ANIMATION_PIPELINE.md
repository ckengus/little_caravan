# 아트·애니메이션 전달 규격

## 1. 현재 자산과 목표

확정 일러스트: [일행 PNG](../assets/art/references/little-caravan-party-v1.png).

현재 확보된 것은 외형 참고용 PNG 한 장이다. 런타임 투명 프레임·무기·스켈레톤·완성된 공격 애니메이션은 저장소에 없다. 이전 GIF 초안은 사용자가 어색함을 지적했으며 최종 승인된 동작이 아니다. GPT가 생성한 전신 그림을 매번 통째로 흔드는 것만으로 공격 완성으로 보고하지 않는다.

목표는 간결한 2D 아트에서 읽히는 자세 변화와 타격감이다. 60프레임 같은 과도한 부드러움은 요구하지 않는다. 아래 장수는 예산 가이드이며 승인된 최종 수치가 아니다.

## 2. 제작 방식과 검증 순서

1. 실제 표시 크기에서 주인공의 무기 포함 전투 기본자세를 결정한다.
2. 무기 없는 몸, 별도 검, 필요한 손 전경 패치를 제작해 합성한다.
3. 준비→타격→마무리→회수→기본자세를 소수의 전신 프레임 또는 필요한 교체 부품으로 만든다.
4. 테스트 필드에서 그립·앞뒤 겹침·발 위치·타격 시점을 확인한다.
5. 두 번째 시험용 검으로 교체가 되는지 확인한다.
6. 이 방식이 통과한 뒤 나머지 캐릭터로 확대한다.

초기 기본 선택은 전신 핵심 프레임 + 별도 무기/손 레이어다. 부위 분리/코드 키프레임은 대기·보조 흔들림과 필요한 구간에 활용할 수 있다. Spine 등 유료 도구·라이선스는 아직 채택하지 않았다. 구조를 바꿔야 하면 작은 비교 샘플과 이유를 기록한다.

## 3. 게임용 전달 묶음

| 파일 | 필수 내용 |
| --- | --- |
| PNG 또는 atlas PNG+JSON | 투명 배경, 일정 비율, 프레임이 잘리지 않는 캔버스 |
| 몸/무기/필요한 손 이미지 | 원본과 합성본 구분; 무기 분리는 실제 파일로 검증 |
| 애니메이션 manifest | 상태명·순서·유지시간·반복·타격 이벤트·복귀 상태 |
| 부착 데이터 | 손잡이 피벗, 프레임별 무기 위치·각도·크기·앞뒤 순서 |
| 출처/상태 문서 | 생성·수정 이력, draft/integrated/approved, 알려진 문제 |
| GIF/영상 | 사용자 검토용; PNG/JSON 원본을 대체하지 않음 |

한 이미지로 헤어·코스튬 교체까지 완성됐다고 간주하지 않는다. 전신 프레임이면 새 의상의 자세별 아트가 필요하고, 분리 방식이면 겹침을 포함한 교체 부품이 필요하다.

## 4. 좌표·레이어 계약

- 각 캐릭터에 발 기준 원점과 기본 표시 크기를 정한다. 캔버스 크기가 바뀌어도 원점을 통해 정렬한다.
- 좌표는 오른쪽 +X, 아래쪽 +Y. 무기 각도는 오른쪽 0°, 아래쪽 90°. 원본 검이 위를 향하면 기준 각도 보정을 명시한다.
- 좌우 반전은 캐릭터·무기·손 좌표·판정 방향을 한꺼번에 반전한다. 장식 비대칭의 방향별 예외는 후순위.
- 앞손/뒷손이 잡는 검 손잡이 기준점을 둔다. 한 손 기준점만 맞추고 다른 손이 미끄러지는 상태를 통과시키지 않는다.
- 무기의 앞뒤 순서는 프레임별로 달라질 수 있다. 무조건 몸 전체 뒤/앞에 고정하지 않는다. 필요한 경우 뒷팔/몸/무기/앞손을 나누거나 해당 자세의 전경 패치를 사용한다.
- 그립을 맞추려고 칼날을 팔 뒤로 숨기지 않는다. 팔·몸통과 칼날 교차가 어색하면 그림/자세를 수정한다.
- pivot, displayScale, drawOrder, weaponSockets, hitEvent 등 필드 이름은 M2 구현 시 실제 스키마와 샘플로 고정한다. 이 문서의 명칭이 곧 구현됐다는 뜻은 아니다.

## 5. 행동 상태와 연결

| 상태 | 필요한 행동 | 첫 제작 가이드 |
| --- | --- | --- |
| idle | 같은 자리에서 양손검을 잡고 작은 들숨·날숨 | 2~3 핵심 자세/작은 변형 |
| walk | 발을 교대하며 이동 | 4자세 수준부터 |
| slash | 준비·베기·마무리·회수 | 4~6자세와 공통 기본자세 |
| thrust | 준비·뻗기·검 회수 | 3~5자세와 기본자세 |
| dash | 방향 이동·제동 | 준비/이동/제동 |
| dashSlash | 전진하며 전방 베기·제동 | 3~5자세, 실제 위치 이동 분리 |
| stagger | 짧은 경직 후 대기 | 1~2 피격 자세 |
| knockback/getUp | 밀려남·낙하·넘어짐·기상 | 자세별 핵심 프레임, 사용자 검수 |

모든 정상 행동의 시작/끝은 **동일한 원본 기본자세**로 연결한다. 비슷한 기본자세를 따로 생성해 교체하지 않는다. 대쉬·넉백 후에는 도착 위치에서 기본자세로 복귀하며 원래 좌표로 순간이동하지 않는다.

공격 중 방향 고정. 초기에는 다른 일반 공격 버튼 입력을 무시하고 입력 버퍼는 넣지 않는다. CC는 현재 동작을 중단할 수 있으므로 공격 중간 피격에서 기본자세를 억지로 끼워 넣지 않는다. 중단된 공격의 남은 타격 이벤트는 취소한다. 경직 중 추가 피격은 테스트 기본값으로 남은 경직을 갱신하고 넉다운 중에는 추가 넉다운을 누적하지 않는다. 이 중첩 규칙은 제품 확정치가 아닌 테스트용 정책이다.

공격은 타격 프레임 이벤트에서 판정한다. 투사체는 발사 이벤트에서 생성하고 실제 충돌/도달 때 피해를 적용한다. 한 공격이 같은 적을 의도치 않게 중복 타격하지 않도록 공격 식별자를 사용한다.

## 6. 아트 제작·적용 협업

- 사용자: 외형·작은 화면 가독성·움직임 최종 검수.
- GPT: 외형/동작 요구 정리, 이미지 생성·수정, 누락 아트 목록과 설명 작성.
- Codex: 자르기·정렬·로딩·패킹·재생·무기 부착·타격 이벤트·테스트 필드 적용. 필요한 경우 좌표 조정 도구 제공.
- 공통: 실제 합성 결과에서 손·검·얼굴·발을 확인한다. 생성 이미지가 안정적인 연속 프레임을 보장한다고 가정하지 않는다.

아트가 없으면 임시 부품/실루엣을 사용하고 기능은 진행한다. 임시 공격을 정식 승인으로 처리하지 않는다. 같은 문제로 생성만 반복하지 말고, 단일 자세·좌표·레이어 중 원인을 먼저 분리한다.

## 7. M2 시각 인수 체크

- 공통 기본자세의 시작/끝이 같고 발 기준점이 튀지 않는다.
- 양손이 손잡이에 붙어 있고 칼날·가드가 올바른 앞뒤 순서로 보인다.
- 공격 준비/타격/회수가 구분되고 타격 반응이 맞는다.
- 좌우 모두 정상이고 두 번째 검 교체도 확인한다.
- 실제 작은 표시 크기와 느린 재생에서 모두 확인한다.
- 기술 검증 통과와 사용자 시각 승인 상태를 따로 기록한다.
